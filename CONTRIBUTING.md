# Contributing

Thanks for your interest in Moderation Bias. This project has two halves: a Python
audit/analysis pipeline (repo root, `src/`, `scripts/`) and a Next.js frontend
(`web/`).

## Dev setup

```bash
# 1. Config
cp .env.example .env         # add OPENROUTER_API_KEY at minimum

# 2. Frontend (no Python needed to run the site)
cd web && npm install && npm run dev   # → http://localhost:3000

# 3. Python pipeline
pip install -r requirements.txt
```

## Before you open a PR

Run the same checks CI runs:

```bash
# Frontend (from web/)
npm run lint
npm run typecheck
npm test
npm run build

# Python (from repo root)
PYTHONPATH=. pytest tests/ -q

# Reproducibility: recompute published stats from the raw data (offline, no API cost)
python reproduce_results.py
```

CI enforces ESLint, `tsc`, unit tests, and the Python test suite. Keep them green.

## Conventions & guardrails

- **Refusal definition is centralized.** Never hardcode a verdict set. Import from
  `src/refusal.py` (Python) or `web/lib/verdicts.ts` (TS). A test asserts they match.
- **The LLM judge must be held out of the subject pool** (`src/judge_config.py`).
  Don't set `JUDGE_MODEL` to a model you also want on the leaderboard.
- **No mock/placeholder data in shipped artifacts.** `web/public/*.json` must come
  from a real pipeline run. The `--mock` path is blocked from writing under `web/public/`.
- **Don't commit generated data or build artifacts** (the large CSV/JSON are gitignored
  and regenerated by the pipeline).
